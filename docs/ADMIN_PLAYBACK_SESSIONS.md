# 管理收听会话

2026-10-14 实现检查点。功能已接入并部署，原窗口部分验收通过；模型、集中构建和窗口结果分别记录，不能互相替代。

## 当前能力

- 服务器历史支持用户下拉、八种排序、升降序、每页10/25/50/100条与分页；本页选择和批量删除。查询变化清除旧选择，用户/历史/活动/分享各自加载、错误与重试。
- 活动会话和分享会话单独显示；用户筛选只影响历史。共享详情显示位置、累计收听、设备、客户端和身份；缺字段显示空缺。分享会话只读。
- 单条历史删除要求删除权限；管理员批量删除遵从上游独立权限；2.26仅允许关闭自己的活动会话，已核对的2.36.1/2.37.1允许管理员关闭其他用户。未知版本保守处理。
- 从历史位置播放必须在线重新读取媒体与权限，精确选择播客单集；已有本机原件优先。起点在播放器开始和第一个持久检查点之前采用，不先从旧进度播放再跳转。它更新当前账户进度，不向被查看用户写进度。断网管理历史播放不在本批实现范围，普通离线续播仍由已有独立链路处理。
- 写入确认只消费一次；服务端已确认与后续重新读取失败分开反馈。管理删除期间暂停同分区音频同步；拒绝删除尚待同步或正在收尾的选中记录，避免旧日志再建历史。租约绑定确切来源与拥有者，旧账户迟回不释放新账户租约，也不阻断新账户播放。
- 精确关闭此Mac的活动会话时先完成本机持久处理；其他设备的会话不停止本机播放器。消费`user_session_closed`时按确切远端session ID匹配，保存本机累计值，不再向已关闭的远端重复sync/close。
- shutdown/configure会等待已经从界面脱离、仍在保存的旧会话；等待期间不允许旧媒体键启动下一首。音频磁盘完全写入失败时现有普通退出路径尚未完成单独故障验收，不宣称此风险已全部解决。
